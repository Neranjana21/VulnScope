# Threat model: attacks against VulnScope itself (STRIDE)

Assets: engagement scope and authorization, credentials by reference, evidence, ledger integrity, the scan plane's network reach, the operator's trust in reports.
Adversaries: a malicious or compromised target; a malicious tenant/operator trying to scan beyond authorization; a compromised dependency or adapter; an insider editing history.

**Reading this table.** "Mitigation" and "Test" state the intended design; they do not say either exists. "Today" is based on the [ADRs](adr/) and, for Step 1, a code review, one fix round and one verifier pass. **No threat is declared mitigated.** "Partial" means some control is recorded, with gaps. "Not verified" means the ADRs do not establish it; it does not prove that no code exists.

| ID | Threat | Category | Mitigation (intended) | Test (intended) | Today (ADR) |
|---|---|---|---|---|---|
| T1 | Target redirect or DNS trick sends the scanner to an out-of-scope or internal host (SSRF-style) | Elevation | Gateway enforces allowlist, resolves and pins IPs, re-checks every redirect, blocks link-local/metadata always | policy property tests; gateway integration test | Gateway planned, not built (0002, 0013). An application-level policy core exists; these ADRs do not detail it |
| T2 | URL parsing differences (userinfo, IDN, trailing dot, alternative IP encodings, IPv4-mapped IPv6) bypass the scope check | Elevation | Single canonical target parser; decide on the resolved IP, not the string | hypothesis tests over a corpus of tricky forms | Partial: API target checks use the policy parser only (0006). Parser coverage and tests not verified; no gateway (0002) |
| T3 | A wrapped tool makes connections the adapter did not plan | Elevation | Workers have no direct egress; only the gateway is reachable | integration test: direct connect attempt fails | Planned; no workers or gateway (0002, 0013) |

## Step 1 development spike (ADR-0013, amended by ADR-0014)
**NOT the security boundary, NOT a Slice 1 result and NOT a Slice 1 pre-gate pass.** It mitigates none of the threats above.

- **Path:** one in-process HEAD on `127.0.0.1`, to the project's own stub or (Step 1b) to the sealed lab app target on port 3000, after a recorded decision. Five headers, literal present/absent only (CSP `frame-ancestors` does not count as `X-Frame-Options`); redirects not followed; findings unscored (0012). No DNS, TLS or real target; tests use only listeners they own.
- **Bypass:** no gateway, worker, queue, job token, process or network isolation. A code bug or in-process code can patch the sender or helpers, call the private send, open its own socket, swap in or inherit another `127.0.0.1` listener, or inject a fake ledger or engagement view (the last is omitted from ADR-0013). Policy does not restrict ports; the sender pins `127.0.0.1`, the exact target text, and the stub port or the constant 3000. The lab target is accepted by object identity only; no command line, environment, configuration, database or API value names a target.
- **Lab app (ADR-0014):** port 3000 cannot identify Juice Shop, so another local server on that port would receive the HEAD (the operator attests the identity). Lab isolation not verified: container and network settings are lab hygiene, not the worker boundary, and a deliberately vulnerable app run by the operator is itself a risk to the host that this project does not contain. Its response is hostile input: only five header names become booleans, under the 16 KiB and 5 s caps.
- **Still open:** SEC-6 and GR-SEC-9, including while a lab app's responses are read.
- **Gaps:** no ledger checkpoint (tail truncation or a rewritten chain is undetectable); the app database role can modify or delete rows and rewind chain heads; no structural log scrubbing (the demo disables logging and prints only exception class names; other callers get raw exceptions); revoke latency not measured; window expiry in flight or before the finding write not shown to be tested; engagement creation bypasses the API; authorization self-attested.
- **Packaging:** exclusion of `devpath/` is shown from build configuration only (no wheel built); the import scan misses non-literal dynamic imports.
- **F1 (T10), fixed with a remaining gap:** status and window are re-read after the recorded allow, before any socket exists; a refusal or failed read sends nothing. A revoke or expiry after that read but before the bytes leave is not prevented, and a refusal leaves the allow entry with no separate refusal entry (accepted for the development spike only; backlog BL-S1-F9: record the abort when Step 2 lands).
- **F2 (T5), fixed with limits:** ledger and rows are compared both ways, with a report-level mismatch or "check incomplete". Some fields are checked only against code constants, and severity, CVSS, priority, asset ID, taxonomy, timestamps and other unlisted fields are not compared. Deletion is detected, not prevented. Editing an unscored finding's severity stops report generation instead of showing a mismatch.
- **F3-F8:** database host not checked (only the name); rate limit applies per run only; ADR-0013 omits the injected fakes; no committed real-database test for window expiry or a failed re-read before sending; the invisible-character guard does not cover `docs/` or `scripts/` (nor migrations or the project file); a failed commit can leave "confirmed" only in the ledger.
